# Дозаполнение бухгалтерской отчётности

Расширение конфигурации 1С для «Бухгалтерии предприятия» (в том числе КОРП), которое дозаполняет регламентированную бухгалтерскую отчётность (форма 2025) по настраиваемым правилам. Правила, которые меняют типовое значение строки, показывают в расшифровке и типовое слагаемое, и свою корректировку, поэтому бухгалтер видит, откуда взялась сумма.

Префикс объектов — `дбу_`. Платформа 8.3.27, режим совместимости `Version8_3_27`.

## Какую задачу решает

Типовое заполнение бухгалтерской отчётности в 1С заполняет баланс по стандартным правилам: строка = сальдо по своим счетам. На практике в группе компаний почти каждый отчётный период бухгалтер правит часть строк вручную, потому что методика учётной политики отличается от того, что делает типовой алгоритм.

Примеры таких правок:
- свернуть или переклассифицировать задолженность: проценты по займам из дебиторской задолженности (1230) в финансовые вложения (1190), долгосрочную часть кредитов из 1510 в 1410;
- зачесть взаимные расчёты внутри группы (свёртка дебиторской и кредиторской задолженности по одним контрагентам);
- заменить типовое значение своим расчётом: аренда по ФСБУ 25, резервы, финансовые вложения по данным отдельного отчёта.

Ручные правки создают проблемы:
- **Они теряются.** Каждый раз, когда отчёт перезаполняют, их приходится вносить заново.
- **Их нельзя проверить.** В отчёте не видно, откуда взялась сумма: проверяющему нужно восстанавливать расчёт по Excel или переписке.
- **Их приходится повторять.** Одна и та же правка делается отдельно в каждой организации группы и в каждом периоде.
- **Они ошибаются в сравнительных графах.** Графы прошлых лет правят «на глаз» или не правят вовсе.

## Как решает

Методика правок один раз описывается **правилами** в 1С, и отчёт заполняется по ним кнопкой **«Заполнить с доработками»**:

1. **Выполняется типовое заполнение.** Его результат не теряется: от него отталкиваются корректировки.
2. **Собираются правила.** Это правила профилей, подключённых к организации на отчётную дату. Один профиль можно подключить к нескольким организациям, а у одной организации может быть несколько профилей.
3. **Считаются суммы.** Каждое правило берёт суммы из учёта: сальдо и обороты по счетам с отборами по субконто, произвольные запросы, специальные расчёты (например, аренда). Затем оно вычисляет формулу и пишет результат в строки отчёта: добавляет, уменьшает или заменяет типовое значение.
4. **Всё видно в расшифровке.** Расшифровка каждой затронутой строки показывает типовые слагаемые и корректировки правил отдельными строками с префиксом профиля, например «КДР: …».
5. **Сравнительные графы считаются так же.** Графы на 31 декабря прошлого и позапрошлого года считаются теми же правилами на свою дату. Поэтому профиль подключают с начала позапрошлого года.

**Защита от ошибок:**
- В карточке правила есть кнопка «Проверить формулу».
- Кнопка «Пробный расчёт» показывает суммы операндов и итог формулы за любой период, в том числе по несохранённым настройкам. Из строки операнда можно открыть ОСВ или анализ счёта с тем же отбором.
- Если сторно снимает не ту сумму, что записала типовая 1С, бухгалтер получает сообщение.

**Права разделены ролями:** одни пользователи настраивают правила, другие только видят и применяют их.

Для аренды по ФСБУ 25 реализован отдельный расчёт по схеме справки-расчёта. Он сам определяет порядок оплаты по договору: обычный, предоплата, постоплата или отсрочка. Подробности: [docs/lease-calculation.md](docs/lease-calculation.md).

## Как это устроено

- **Профиль доработки** (`дбу_ПрофилиДоработки`) — набор правил. В табличной части «Применения» указывается, к каким организациям и с какой даты профиль подключён (`ПрименятьС` / `НеПрименятьС`, приоритет, признак активности). Префикс расшифровки профиля добавляется к названиям строк в расшифровке.
- **Правило доработки** (`дбу_ПравилаДоработки`) принадлежит профилю. Оно состоит из:
  - **операндов**: остатки и обороты по счетам с отборами по субконто, данные произвольного запроса или специальные способы расчёта, например аренда;
  - **формулы** над операндами;
  - **целей**: строки отчёта (стандартная, вписанная, прямая или вложенная расшифровка), графы и действия («Добавить», «Уменьшить», «Заменить типовое значение»).
  У правила есть свой период действия и приоритет.
- **Запрос данных** (`дбу_ЗапросыДанных`) — произвольный запрос или отбор СКД с параметрами для операндов.
- **Заполнение**. В форме регламентированного отчёта появляется команда «Заполнить с доработками». Сначала выполняется типовое заполнение, затем правила профилей, подключённых к организации на отчётную дату. Результат записывается в расшифровку строк.
- **Роли**:
  - `дбу_ОсновнаяРоль`;
  - `дбу_ЧтениеНастроекКДР` — только просмотр настроек;
  - `дбу_ИзменениеНастроекКДР` — изменение настроек.

Отдельно реализован расчёт арендных обязательств по ФСБУ 25 по схеме справки-расчёта: [docs/lease-calculation.md](docs/lease-calculation.md).

## Установка из исходников

Нужна информационная база «Бухгалтерии предприятия» 3.0 на платформе 8.3.27 или новее.

1. **Загрузка.** Конфигуратор → Конфигурация → Расширения конфигурации → добавить расширение `ДозаполнениеБухгалтерскойОтчетности` → Конфигурация → «Загрузить конфигурацию из файлов…» → каталог `src/cfe/ДозаполнениеБухгалтерскойОтчетности`.
2. **Обновление БД.** «Обновить конфигурацию базы данных».
3. **Свойства расширения.** Снять «Безопасный режим» и «Защита от опасных действий»: расширение читает регистры бухгалтерии и данные регламентированного отчёта.

То же самое в пакетном режиме:

```
1cv8 DESIGNER /S <сервер>\<база> /N <пользователь> /P <пароль> ^
  /LoadConfigFromFiles src\cfe\ДозаполнениеБухгалтерскойОтчетности -Extension ДозаполнениеБухгалтерскойОтчетности ^
  /UpdateDBCfg -Extension ДозаполнениеБухгалтерскойОтчетности
```

Готовый `.cfe` можно собрать из загруженного расширения командой «Сохранить конфигурацию в файл…».

## Тесты

Тесты написаны на [YAxUnit](https://github.com/bia-technologies/yaxunit) и загружаются отдельным расширением из `tests/cfe/ДозаполнениеБухОтчетностиTests` так же, как основное. Им нужна тестовая база с хотя бы одной организацией и проводками.

**Не запускайте тесты на рабочей базе.** Тесты создают и оставляют в базе:
- профили и правила;
- пользователей ИБ для проверки ролей.
